## 3. Rollback SOP 三路徑

| 路徑 | 時間 | 風險 | 用法 |
|---|---|---|---|
| **A. Vercel 一鍵** | 30 秒 | 低 | Dashboard → Deployments → 上一個成功 → Promote to Production |
| **B. `vercel rollback`** | 30-60 秒 | 低 | `vercel rollback <deployment-url>` |
| **C. git revert + push + vercel** | 3-5 分鐘 | 中 | `git revert HEAD` → push → `vercel --prod --yes` |

**強制規則**：永遠先 A → B → C；rollback 完必寫 incident report。

## 4. Post-Deploy Watch 觸發條件

```bash
~/.hermes/scripts/production-watch.sh <url> 5m
```

每 30s curl 一次，觸發以下任一即報警：

- HTTP status 非 2xx
- response time > 3 秒
- 連續 3 次失敗

**任一觸發 → 自動建議 rollback 路徑**。

實測：4 次成功（HTTP 200, 1ms）+ 3 次失敗（port 9999 不存在）皆正確觸發。

## 5. Notion PATCH 半自動化

之前 E1 是「印提醒要人手動跑」；v0.2 升級為：

- 偵測 Notion token 是否存在
- 自動印出預填指令（Stage 1 + Stage 2 分開）

```bash

  --status '✅ 已通過 Production-Ready Checklist' \
  --vercel 'https://<prod>.vercel.app' \
  --note 'release-notes: <path>'
```
